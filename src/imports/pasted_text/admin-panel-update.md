ТЗ на точечную доработку существующей админ-панели
1. Общие указания

Доработай уже созданный макет админ-панели. Не создавай проект заново и не меняй существующую визуальную концепцию.

Необходимо сохранить без изменений:

общий дизайн админ-панели;
левое боковое меню;
главную страницу;
существующий раздел «Подрядчики»;
отдельный раздел «Сотрудники»;
таблицы сотрудников;
формы добавления и редактирования сотрудников;
существующую карточку сотрудника;
цветовую палитру;
типографику;
кнопки, поля, карточки и другие готовые компоненты.

Все новые элементы должны быть выполнены в том же стиле, что и уже созданный интерфейс.

К запросу приложены референсы:

Текущий реализованный макет админ-панели.
Страница «Метки» из исходного проекта.
Текущая карточка сотрудника.
Блок «История активности» из исходного проекта.

Используй их только для внесения описанных ниже изменений.

5. Новая страница «Метки»

Создать одну новую страницу для управления NFC-метками.

Визуально она должна соответствовать текущей админ-панели. Приложенная страница «Метки» из исходного проекта используется как функциональный референс, но новую страницу необходимо оформить в дизайне уже созданной админки.

Назначение страницы

Пользователь должен иметь возможность:

видеть список всех NFC-меток;
видеть ID и UID каждой метки;
назначать метку подрядчику;
назначать метке действие «Вход» или «Выход»;
быстро перераспределять метки через drag-and-drop;
возвращать метки в список свободных.

8. Drag-and-drop распределение меток

Основным режимом страницы должна быть доска с drag-and-drop.

Она состоит из:

Списка свободных меток.
Карточек подрядчиков.
Зон «Вход» и «Выход» внутри каждого подрядчика.
8.1. Свободные метки

Слева разместить отдельную колонку:

Свободные метки

Подзаголовок:

Не назначены подрядчику

Показывать количество свободных меток.

Внутри разместить карточки, которые можно перетаскивать.

8.2. Карточка метки

На каждой карточке показать:

ID;
UID;
название объекта;
текущее действие;
текущего подрядчика, если назначен.

Пример:

Метка #53

UID: 049B1F3C60AA81

Логистический центр «Запад»

Не назначена

Добавить иконку захвата для drag-and-drop.

UID отображать моноширинным шрифтом.

8.3. Карточки подрядчиков

Справа от свободных меток расположить карточки подрядных организаций.

В заголовке карточки:

название подрядчика;
количество назначенных меток.

Пример:

ООО «Альфа Строй»

Назначено меток: 8

Внутри каждой карточки должны находиться две отдельные зоны.

Зона «Вход»

Заголовок:

Вход

Подсказка:

Перетащите сюда метку для регистрации входа

Зона «Выход»

Заголовок:

Выход

Подсказка:

Перетащите сюда метку для регистрации выхода

8.4. Логика перетаскивания

При перетаскивании свободной метки в зону «Вход» система визуально назначает:

выбранного подрядчика;
действие «Вход».

При перетаскивании в зону «Выход»:

выбранного подрядчика;
действие «Выход».

Таким образом, одно перетаскивание должно одновременно определять подрядчика и действие метки.

Метка должна поддерживать перенос:

из свободных к подрядчику;
от одного подрядчика к другому;
из зоны «Вход» в «Выход»;
из зоны «Выход» во «Вход»;
обратно в свободные метки.
8.5. Состояния drag-and-drop

Во время перетаскивания:

карточка немного увеличивается;
появляется выраженная тень;
курсор меняется на grabbing;
доступные зоны подсвечиваются.

При наведении на зону показывать текст:

Назначить как «Вход»

или:

Назначить как «Выход»

После успешного назначения показать toast:

Метка #53 назначена ООО «Альфа Строй» как «Вход»

В toast добавить действие:

Отменить

Не показывать модальное подтверждение при каждом перемещении.

11. Добавление истории посещённых объектов

В существующей карточке сотрудника добавить новый блок или отдельную вкладку:

История посещений

Предпочтительный вариант — добавить в верхней части карточки две вкладки:

Данные сотрудника.
История посещений.

По умолчанию открыта вкладка «Данные сотрудника».

Вкладка «История посещений» должна показывать, на каких объектах находился сотрудник, а также дату и время посещения.

12. Визуальное дерево истории

Историю оформить в виде вертикального дерева, аналогичного блоку «История активности» из приложенного исходного проекта.

Сохранить принцип референса:

вертикальная соединительная линия;
круглые точки событий;
записи располагаются последовательно вдоль линии;
последнее событие выделяется синим;
остальные события отображаются более нейтрально;
рядом с точкой показывается информация о посещении.

Не копировать старые данные из референса. Использовать историю объектов сотрудника.

13. Содержание события истории

Для каждого события показать:

название объекта;
дату;
время;
тип события «Вход» или «Выход».

Пример:

Логистический центр «Запад»
10 апр., 11:25
Вход

Следующее событие:

Логистический центр «Запад»
10 апр., 15:40
Выход

Другой объект:

БЦ «Орион»
9 апр., 09:10
Вход

События отображать от новых к старым.

14. Отображение текущего положения

На объекте

Покинул объект

18. Что не требуется делать

В рамках этой доработки не нужно:

пересоздавать всю админ-панель;
менять главную страницу;
переделывать готовый список подрядчиков;
переделывать готовый список сотрудников;
заново создавать формы сотрудников;
менять дизайн-систему;
менять цветовую палитру;
добавлять новые глобальные разделы, кроме «Метки»;
переносить «Объекты» в боковое меню;
удалять самостоятельный раздел «Сотрудники»;
создавать полноценный журнал выполненных сотрудником работ;
добавлять заметки и отчёты сотрудника в историю посещений.

История в карточке сотрудника должна показывать только посещённые объекты, даты, время и события входа/выхода.

20. Критерии готовности доработки

Доработка считается выполненной, если:

существующий макет не пересоздан;
в настройках удалена только внутренняя вкладка «Сотрудники»;
в настройках появилась вкладка «Объекты»;
порядок вкладок: «Объекты», затем «Подрядчики»;
самостоятельный раздел «Сотрудники» остался в боковом меню;
добавлен новый пункт «Метки»;
создана страница распределения меток;
метки можно назначать подрядчикам через drag-and-drop;
через drop-зону назначается действие «Вход» или «Выход»;
метки можно переносить между подрядчиками и возвращать в свободные;
предусмотрен табличный режим;
существующая карточка сотрудника сохранена;
в карточке добавлена история посещённых объектов;
история оформлена как вертикальное дерево из референса;
в каждом событии показаны объект, дата, время и тип события;
все новые элементы выполнены в стиле существующей админ-панели.
